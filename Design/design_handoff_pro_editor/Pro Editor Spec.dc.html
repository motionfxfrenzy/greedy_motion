1 · Decision

Option 1 · One editor, two modesRecommended

One Studio shell. The mode switch (Layers / HTML clips) follows the composition: each composition belongs to one engine, so switching mode is switching composition. The bridge is an action inside the shell, not a hand-off between apps.

  • One place to learn: same top bar, timeline, inspector, render, checks, review.
  • The bridge stays in context: select a clip, Send to Layers, and you land on the new 3D layer.
  • One undo history and one render queue for the whole project.
  • Cost: the shell has to hide controls that don't apply to the current engine.
Option 2 · Two editors, one library

Separate Layers and HTML clip editors built from the same components. Each opens its own composition. The bridge exports from one app and imports into the other.

  • Each UI is simpler and can follow its engine closely.
  • Two undo histories and two render queues to explain.
  • The bridge becomes a cross-app round trip with a file in between.
  • Users who work in both engines switch apps a lot.

3 · Interaction spec

Motion 180–260 ms, cubic-bezier(.16,1,.3,1), no bounce. Drags start after 3 px of movement. Esc cancels any drag and restores the start state. Each finished drag is one undo step.

6 · Reference: OpenCut

OpenCut (MIT) is a clip-based editor; the main repo is being rewritten around a Rust core with an editor API, plugins and a headless mode. The archived classic version is the working one. Worth reusing as reference: its timeline snapping, trim and track code, and the idea of an editor API that exposes commands, which is how ⌘K gets the engine's command list here. Not worth reusing: its dark visual style and its compositor, since EffectCraft and HyperFrames already render.
