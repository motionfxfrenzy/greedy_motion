# Plate scenes: authoring on the API, drawing and assembly on the worker

> Status (2026-11-04): implemented and verified locally with separate API and worker containers; **not yet deployed**.
> Staging and production are unchanged. See [Release status](#release-status) for what has and has not been verified.

"Plate scenes" are the code-drawn illustration styles (`illus-*`: crayon, paper cut-out, blueprint, …). Every scene of a
storyboard is a small TypeScript module that the model writes in the style's own medium; the **anidoodle** engine draws it
frame by frame on a canvas in Chromium and an MP4 is encoded from the frames. Until now all of that ran inside the Railway API
process (a gitignored developer folder, Chromium and FFmpeg on the API host, state in files on its disk). It is now split along
the platform's existing boundaries.

## Where each part runs

| Part | Runs on | Why |
| --- | --- | --- |
| Frontend (preview, comments, subtitles, export buttons) | Vercel | unchanged |
| Authoring: model call, source validation, **bundling** (esbuild, no execution), uploads | Railway API (`plate-author` queue) | bounded, I/O-bound, no browser |
| Verification in Chromium, frame rendering, FFmpeg encode, **final assembly** (voice, music, effects, subtitles, watermark) | AWS ECS Fargate worker (`plate-render`, `plate-export`, `render-video` kind `plate-film`) | CPU/RAM-heavy, the existing worker image |
| State, queues, fencing | Supabase Postgres (`app.plate_variants`, `app.plate_exports`, pg-boss) | durable, transactional |
| Source, bundles, audio, stills, clips, exports | Cloudflare R2 (`plates/<project>/…`) | the API and worker share no disk |

Chromium and FFmpeg-for-rendering are **not** in the backend image (it already shipped `ffmpeg` for other features; plates no
longer use it). Local disk on either side is scratch and a disposable cache only: deleting it loses nothing.

## The engine package

`packages/plate-engine` (`@videosaas/plate-engine`) is a tracked, versioned vendor copy of the anidoodle engine **0.6.4**
(Apache-2.0, see `LICENSE`, `NOTICE`, `PROVENANCE.md`): the canvas runtime, the 31 style plates and their kits, the browser host
page, the scene bundler and the capture adapter. About 60 files, 1.2 MB. No generated scenes, caches, outputs or experiment
dependencies. `manifest.json` (generated by `npm run manifest -w @videosaas/plate-engine`, checked in) lists the supported
styles and the files each one depends on; style availability comes from it, never from a developer path. Pinned: esbuild
0.25.12, playwright-core 1.63.0.

* `lib/engine.mjs` – manifest, digests, `validateSceneSource`, `bundleScene`. Runs on the API. Generated source is **never
  executed there**; it is parsed and bundled by esbuild through a closed resolver (relative imports inside the engine's `src/`
  only; the allowed imports of a scene are the core modules plus whatever its plate itself imports).
* `lib/capture.mjs` – opens a bundle in Chromium, verifies, renders, encodes. Runs on the worker only. The page is loaded from a
  file the worker wrote; every other request is aborted, service workers are blocked, no secret is ever placed in a page.
* `lib/rules.mjs` – assembly rules shared by planner and worker (`canStreamCopy`).

Rendering clock and frame capture are exactly the previous ones (`FILM.seek(n)` then the canvas PNG, encoded with the same
x264 settings), so output is unchanged: see [Fidelity](#fidelity).

## Render contract

A bundle is one self-contained HTML file plus `manifest.json` (`schema 1`, `kind "anidoodle"`): engine version and content
digest, style digest, width/height, fps (30), integer frame count, aspect, source and bundle SHA-256, and the import list. Jobs
carry only `{ variantId, gen }` (render) or `{ exportId }`; the worker reloads the row and reads artifacts by key. Keys are
validated against `plates/<project-uuid>/…` for the row's own project. The HyperFrames path is untouched: plate work is a
separate renderer kind in separate queues, and `render-video` only gained a `plate-film` input kind (same claims, fencing,
progress, retries and completion as every other final render). `/capabilities` on the worker now reports `plates`.

## Data model (migration `018_plate_pipeline.sql`)

* `app.plate_variants`: one row per (project, scene, **aspect ratio**). `signature` is the artwork's full dependency hash.
  `gen` is raised every time the row is reset (inputs changed, comment revision); `render_attempt` is raised on every worker
  claim. States: `queued → authoring → bundled → rendering → drawn | failed`. Artifact keys are generation- and attempt-specific.
* `app.plate_exports`: companion exports of one ratio (idempotent per signature).
* `app.plate_garbage`: prefixes of superseded generations, swept twice (1 h, then 24 h later).
* `app.plate_state` (kept): comments and subtitle/audio settings per project. Its old `scenes` array is retained as
  `legacy_scenes` for reference only; **Postgres is authoritative and an empty result never falls back to files**.

## Lifecycle

```
POST /plates/draw ─▶ reconcileVariants (one tx per project: rows + plate-author messages commit together)
                        │
   plate-author (API) ──┴─▶ model call ─▶ validate ─▶ esbuild bundle ─▶ upload source/bundle/manifest to R2
                              └─ commitBundle: row → bundled + plate-render message, one transaction
   plate-render (worker) ─▶ claim (atomic, attempt++) ─▶ verify first/middle/last frame twice + on a 2nd page
                              ├─ scene-code defect ─▶ back to authoring (bounded repair, same row)
                              ├─ browser/worker/storage/network failure ─▶ same bundle retried, no model call
                              └─ ok ─▶ render frames ─▶ ffprobe (frames, size, fps) ─▶ upload clip-a<n>.mp4 ─▶ fenced publish
   render-video / plate-export (worker) ─▶ wait for scenes ─▶ assemble ─▶ upload ─▶ ordinary completion/billing
```

Failure categories are never mixed: **invalid source or a failing scene** (bad import, does not bundle, non-deterministic,
throws while drawing, wrong frame count) spends the bounded model budget (`PLATE_MAX_AUTHOR_CALLS`, default 3 calls per
generation, repairs included); **infrastructure** (model API down, browser start-up, Spot interruption, storage, queue) retries
the same row/bundle through pg-boss and never spends it. Unclassified errors count as infrastructure. When storage fails after the
model answered, the bundled module is parked in `draft_source` so the retry needs no new call. Exhausted work fails in plain words
(`error.message`), with the engine detail in `error.detail`.

Ownership and recovery:

* Authoring: atomic lease (`author_owner`/`author_until`, renewed every 25 s), per-project cap, fenced by `gen`.
* Rendering: atomic claim with an advisory lock per project (cap `PLATE_PROJECT_CAP`, default 2), takeover of a silent attempt
  (`PLATE_STALE_SECONDS`, 90 s) raises `render_attempt`; the worker writes progress every 2 s and drops its work the moment a
  fenced write affects 0 rows (superseded). Publication is `update … where gen = $ and render_attempt = $ and state = 'rendering'`;
  a loser deletes the objects it uploaded.
* A changed storyboard raises `gen`, so every in-flight write of the old generation is fenced out; old artifacts go to
  `plate_garbage`.
* Duplicate delivery is harmless: claims are atomic and idempotent.
* **Lost messages**: `reconcilePlates()` (backend, every 30 s while work exists, 120 s idle, and at start) re-sends a message for
  any row that waited > 90 s in a state that needs one, asks for workers (`kickWorkers`) while work is open, and sweeps garbage.
  The ECS launcher counts plate demand from the tables (not the minutes-old queue statistics), so workers also come back after a
  failed `kickWorkers()` or when all workers exited with rows still waiting; the worker's idle-exit also looks at those tables.

## Cache signatures

`variantSignature` (prefix `v3:`) hashes: pipeline version, style id, **engine content digest**, **style digest** (plate + kit +
everything they import), **prompt digest** (contract text + worked example + version), film brief, the list of scene keywords
(the shared cast), the scene's visual / on-screen text / narration, frame count, fps, aspect, pixel size. It deliberately does
**not** include music, voice volume, effects or subtitle settings (they only touch the export) nor the other scenes' pictures.

| Change | Result |
| --- | --- |
| Draw pressed, nothing changed | nothing queued, no model call |
| Music / subtitle / effects / position change | artwork reused; a new export signature re-assembles |
| One scene's visual or line | that scene's variants (all ratios) only |
| Film brief, a scene keyword, style, engine or prompt version | every dependent scene |
| Another ratio selected | only the missing variants are authored and drawn |
| Voice length change | the scene whose frame count changed |
| Comment revision | same signature, `rev` and `gen` + 1, previous source sent with the notes |

Legacy `v2:` signatures (and 16-char v1) are never accepted: this migration is a **one-time invalidation**, because the old
clips lived only on the old API disk and were never in R2. Existing plate projects redraw when Draw is pressed (the preview does
this automatically on open).

**Decision to be aware of:** the prompt shows the model all scenes' visuals as story context, but they are not in a scene's
signature, so editing scene 3 does not redraw scene 4. Recurring objects stay consistent through the film brief and keywords and
through the primary ratio's authored module being passed as a reference to the other ratios.

## Aspect ratios

16:9 1920×1080, 9:16 1080×1920, 1:1 1080×1080, each authored, verified and drawn natively. The primary ratio is queued
first; other ratios wait until the primary's module of the *same scene* exists and then author with it as a reference (same
characters, palette and composition, recomposed natively). Authoring is capped per project (`PLATE_PROJECT_CAP`-style cap
`PLATE_PROJECT_AUTHOR_CAP`, default 4) and per API instance (`PLATE_AUTHOR_CONCURRENCY`, default 3); rendering per project (2) and
per worker task (`PLATE_CONCURRENCY`, default 2). All variants persist independently.

## Final assembly

One authoritative timeline of **integer frames**: a scene lasts its drawn frames, or longer if its voice take plus 0.25 s needs
more; never shorter (`buildTimeline`, `backend/src/plates/model.ts`). Subtitle cues, effect offsets and the encode all read it.
The backend writes an **export manifest** to R2 (timeline, per-scene clip, audio keys, cues, effects, subtitle style/position,
watermark flag); audio is copied once into R2 under its content hash. The worker (`worker/src/plates.mjs → assemble`):

* **stream copy** only when every clip's *probed* frame count equals the timeline, size/fps/codec/pixel format match, and there
  is no subtitle or watermark overlay; otherwise it encodes (scale/pad, retime a clip to its slot, overlays);
* voice per scene at its start frame, looped/faded music at 0.22, word-aligned effects and optional transition sounds, mixed with
  `amix` exactly as before; the output is probed and must have exactly the timeline's frames.

The **Free plan's "Made with Greedy Motion" mark is now applied to plate films too** (it was previously dropped for them although
the render job carried the flag). This is a deliberate behaviour change that follows the plan table (`PLANS[tier].watermark`).

Billed final render: `prepareFilm` makes sure every scene exists (`startPlates`), writes the manifest, and queues an ordinary
`render-video` job of kind `plate-film`; the worker waits for the scenes (progress is reported as drawn scenes), assembles and
uploads `renders/<job>/a<attempt>.mp4`; completion, refunds and the download link are the existing ones. Companion exports
(`POST /plates/export`, free) use `plate-export`; the browser asks once and follows progress.

## Serving

`GET /plates/:i/clip|still?aspect=` (media token as before) 302-redirects to a 15-minute presigned R2 URL (range reads are R2's);
`GET /plates/export/:ratio` redirects to the finished file as an attachment. The frontend's clip URL carries a per-variant version
so a redrawn clip is fetched again.

```bash

node backend/test/plate-model.mjs
DATABASE_URL=postgres://videosaas:videosaas@localhost:55432/plates_unit node backend/test/plate-store.mjs
```

The stack has its own database (`plates_e2e`), shares nothing between the API and worker containers but Postgres and the object
store, and answers model calls from fixed fixture modules.

### Not verified / blocked

* **Staging was not deployed.** This environment has no AWS credentials (`aws sts get-caller-identity` fails), so the worker image
  cannot be pushed to ECR or the task definition updated, and a backend without a capable worker would not exercise anything. Nothing
  on Railway, Vercel, AWS or R2 was changed; production is untouched. Real R2, ECS Fargate, scale-from-zero and the staging end-to-end run
  are therefore **untested**. The migration, images, flag and commands are ready (below).
* The ECS launcher (`WORKER_LAUNCH=ecs`) was not exercised: the stack runs `WORKER_LAUNCH=external`. The new demand counting
  (`plateDemand`) and the reconciler's `kickWorkers` call are covered only by reasoning and the table-level tests.
* Authorization of clips/stills/downloads with real tokens, token charge/refund and entitlement paths were exercised only with
  `AUTH_MODE=none` (the billed final render succeeded once; the refund-on-failure path for a `plate-film` job was not forced). The
  routes keep the existing `/v1/projects/:id/…` access hook and media-token whitelist (`auth.ts`) unchanged.
* Subtitle fonts: the worker image has Liberation/DejaVu; the previous API image had no font packages at all. Output text therefore
  may differ from what Railway rendered before; check on staging.
* In the browser only the preview player, ratio switch, comment panel and the Final render page were looked at; comment, redraw,
  voice preview and subtitle controls were verified through the API, not clicked.
* Not implemented: deleting a project's plate artifacts when the project is deleted, an R2 lifecycle rule for `plates/*` (superseded
  generations are swept; finished exports are kept), per-user quotas on authoring.
* The 31-style manifest was verified to bundle for the three fixture styles only; the other styles share the engine core and plate
  structure but have not each been drawn through the pipeline.

## Production release and rollback plan

Order matters; every step is reversible until step 6.

1. **Worker image first** (backward compatible: it serves HyperFrames jobs exactly as before and only consumes plate queues if the
   backend created them). Build from a clean worktree of the release commit, `ENV=<env> infra/aws/deploy-worker.sh` (see
   `docs/` worker deploy notes), record the image digest, confirm `GET /capabilities` on a running task lists `plates`, run the
   worker self-test.
2. **Backend** with `PLATE_PIPELINE=off` (default). Migration `016` is additive (new tables, new nullable columns on
   `app.plate_state`); nothing reads it while the flag is off. pg-boss gets five new queues. Existing workers ignore unknown queues.
3. Set on Railway: `PLATE_PIPELINE=worker` only on **staging** first. Keep `WORKER_LAUNCH=ecs`; no new AWS variables are needed (the
   worker reads `plates/*` through the existing uploads/outputs credentials). Confirm the worker task role can read the uploads bucket
   and write the outputs bucket (already required for renders).
4. **Staging acceptance** (repeat on real R2/ECS): draw 3 scenes × 3 ratios, export each, final render, then
   durability checks: stop the ECS tasks while rows are `rendering` and confirm they resume; let all tasks idle-exit with a
   scene `bundled` and confirm `reconcilePlates`/`kickWorkers` starts a task; kill the API during authoring. Record image digests,
   timings (authoring, queue wait incl. cold start, verification, render, export), model-call counts, output links.
5. **Frontend** (Vercel) from the same commit; it works with the flag on or off.
6. Production: repeat 1–5 with `PLATE_PIPELINE=worker`. Existing plate projects redraw on first Draw (one-time invalidation).

**Rollback**: set `PLATE_PIPELINE=off` (instant; plate styles report unavailable exactly as before, in-flight rows simply stop being
served) → redeploy the previous backend if needed (the migration stays; it is additive) → the previous worker image keeps working
(unknown queues are never consumed; a `plate-film` job queued by the new backend would fail permanently with "unsupported" and be
refunded, so drain plate renders first). No data needs to be restored: HyperFrames projects never touched the new tables.
