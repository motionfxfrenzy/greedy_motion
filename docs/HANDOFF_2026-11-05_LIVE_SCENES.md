## 0. One-paragraph summary

The product has two film engines: **plates** (model-written canvas code, "illus-*" looks, rendered to MP4 by a CPU-only AWS worker) and **HyperFrames** (HTML/GSAP compositions played in `<hyperframes-player>`). The goal of this programme: **both engines share one workflow and one UI** (script, storyboard, animation step, final review), the animation step shows the scene **code drawn live in the user's browser** (no MP4 per edit; comments change code or parameters, not a render), and the final MP4 is rendered once, on the AWS worker, from exactly the revisions the user previewed. In parallel, the render workers were changed so they **hold no database connections** ("job control"), which removes the Supabase pooler limit that capped production at one worker. As of now all of that is built, tested locally and reviewed, and **staging runs the new backend, frontend and worker** (live-preview flags still off). **Production is untouched.** One phase (4a, HyperFrames element/scene edits) is running on the coding agent. Remaining: finish staging validation, phases 4b and 6, optional 3d, production rollout, and a few clean-ups (section 10).

## 2. Architecture decisions (what the product now is)

Full detail: `docs/LIVE_SCENES_PLAN.md` sections 17 to 25. Essentials:

* **Authoring** (model call, validation, esbuild bundle) runs on the backend as a queued `plate-author` job; the bundle is one self-contained HTML file in R2 (`uploads` bucket); Postgres holds metadata, digests, revisions (`plate_revisions`).
* **Step 3 drawing** (plates): in the **user's browser**, in a terminable Worker with `OffscreenCanvas`, created from a sandboxed, CSP-locked bootstrap iframe (`sandbox="allow-scripts"`, no same-origin; CSP `default-src 'none'; script-src 'unsafe-inline'; worker-src blob:; connect-src 'none'; img-src data: blob:`). Frames go to the page as transferred ImageBitmaps; a byte-budgeted rolling window (`computeRollingWindow`) holds ~2 s ahead at the default 160 MB. Watchdog: draw over 2 s or missed heartbeat terminates and recreates the Worker; 2 terminations mark the scene unhealthy, so it plays its **clip** instead; Worker recycled per scene boundary and after 60 s of lifetime (recycling reduces retention only; peak memory is not bounded and cannot be read; documented). **Live is the default, the MP4 clip is a per-scene fallback** (slow draw, unhealthy host, unverified browser, over budget). Only desktop Chromium >= 120 is `verified`; Safari/Firefox/iOS/Android are `unverified` and get clips until someone measures them.
* **Step 3 for HyperFrames**: already drawn live in `<hyperframes-player srcdoc>`; edits (captions mode, voice/music) are a plan patch plus a composition reload (HTML only, no MP4).
* **Comments**: the shared UI is one timed-comment panel. Plates: scene revision through the authoring job (parameter patch path is phase 4b). HyperFrames: storyboard line rewrite per scene today; element/scene-level edits are phase 4a (running). Decision: an edit that cannot affect any other element is applied at **element level** instantly; anything that affects other elements or layout (size, longer text, moving into another element's space) is **scene level** and re-lays-out the whole scene; the **system decides by measurement** (apply, then check other elements' boxes, overlaps, safe area), not the model (`docs/LIVE_SCENES_PLAN.md` 23; brief `tools/phase4/TASK-element-edits.md`).
* **Step 4 / final render** (phase 5): the Render click freezes a **schema 2 export manifest** (per scene `bundleDigest`, `bundleKey`, params, plus audio digests, subtitles, engine/font digests) in object storage under a content-addressed key; the **worker verifies every bundle first, then draws missing scenes itself** (software GL self-check; clip cache `app.plate_clips` keyed by digest+engine+font+size; shared with preview fallback clips), then assembles. A scene failing verification stops the render before any frame, refunds the user, and returns as a repair revision ("needs fix"); nothing a user does after clicking Render changes that render. A final render makes **zero `plate-render` jobs** now; `plate_state.draw_aspects` is unused (the cost leak is closed). Billing: spend at click, refund exactly once on any failure except user cancel; optional `Idempotency-Key` header.
* **Digest identity**: `bundleDigest = sha256(bundleSha | paramsDigest | fontSetDigest | engineDigest)`. Note: the engine's `bundleSha` is `sha256(html + "\0")` truncated to 24 hex (a quirk; verification accepts both forms).
* **Shared UI**: `frontend/components/animation-workspace/` (3a) is the shell for step 3 of both engines (`AnimationWorkspace`, `OptionsBar`, `ControlRow`, `SceneTabs`, `CommentsPanel`, `AnimationPrep`, `ProgressButton`, `StatusLine`), `FinalView` (3e) for step 4. Capability contract (plan 22): every engine provides play/pause/seek/volume/fullscreen/ratio/scene tabs, voice and music on/off, captions off/key phrases/full, timed comments + apply, render; extras (caption style/size/colour/opacity/position, SFX/transitions) are shown only when an engine supports them and never disabled. HyperFrames shows only audio (voice, music, only if the track exists) and caption mode today; styling would come with optional phase 3d.
* **Job control** (`docs/JOB_CONTROL.md`): workers talk HTTPS to backend routes `/internal/worker/*` (bearer `WORKER_CONTROL_TOKEN`; routes exist only when the token is set): long polls (<= 25 s), one dispatcher fetch loop per queue, leases renewed by heartbeat, attempt number fences stale workers, named operation allow-list, finish/drawn/ready idempotent, claims never retried. Workers have no `pg`/`pg-boss`. Measured locally: 0 worker DB connections with 1 to 100 simulated workers; recommended budgets in JOB_CONTROL.md (API pool 5 on the 15-client pooler; roughly 20 to 25 worker tasks possible; **extrapolated from a laptop, not measured on AWS**).
