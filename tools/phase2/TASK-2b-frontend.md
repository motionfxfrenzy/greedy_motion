## What phase 2b delivers

A self-contained, tested browser module that plays one plate scene live: it runs the scene's bundle inside a terminable Worker on an `OffscreenCanvas` (contained as in section 10), keeps a byte-budgeted rolling window of frames, and implements the existing `ScenePlayer` interface. ### 1. The Worker host: `frontend/lib/live/worker-host.ts`
Turn the spike's `createHost` and worker source into product code, with these exact properties:
- **Containment (section 10):** a trusted **bootstrap iframe** (`sandbox="allow-scripts"` with NO `allow-same-origin`, `display:none`) whose `srcdoc` holds host-written code only and a CSP meta tag `default-src 'none'; script-src 'unsafe-inline'; worker-src blob:; connect-src 'none'; img-src data: blob:`. The iframe creates the Worker from a blob and hands a `MessageChannel` port to the page. **Model code runs only inside the Worker.** Frames travel Worker to page directly over that port as transferred `ImageBitmap`s.
- **Worker source** is built by the host from the bundle HTML: a prelude (shim for `window`, `document.getElementById("film")` returning an `OffscreenCanvas`, `document.createElement`, an `Image` shim backed by pre-decoded `ImageBitmap`s with a `drawImage` unwrap for `__ASSETS__` data URLs, as in the spike's final `harness.js`), then the bundle's inline scripts, then the message handler. The Worker must NOT hold a reference to the page, must have no network (the CSP enforces this; do not rely on deleting globals), and must never receive user data.
- **Protocol** (all messages carry an `id` for request/response): `init {scale, params}` returns `{w,h,meta}`; `frame {n}` returns `{n, bitmap, drawMs}`; `hb` returns immediately (heartbeat); `dispose`. Params are passed at construction as canonical JSON and exposed to the scene as `self.__PARAMS__` before the scene scripts run (as the spike's `build-params`/`paramEdit` did); today they are `{}`.
- **Watchdog and recycling** (sections 10 and 0b): the host sends heartbeats; a draw over 2 s, or no heartbeat reply for 2 s, terminates the Worker (`worker.terminate()` and removing the iframe) and recreates it; after two terminations of the same scene the host reports `unhealthy` so the caller falls back to the clip. Recycle (terminate and recreate) at every scene boundary and after a fixed **Worker lifetime** of 60 s counted over all time the Worker is alive (playing, buffering, scrubbing), not playback time alone. Document in code that recycling reduces retention only and does not bound a scene's peak memory.
- **Host-side byte count:** the host tracks the bytes of every frame and bitmap it holds (width x height x 4) and refuses to hold more than its budget; it closes (`bitmap.close()`) every bitmap on eviction, replacement, and destroy.
- **Feature detection**, exported separately: `supportsWorkerHost()` returns false when `Worker`, `OffscreenCanvas` 2D, `createImageBitmap`, or sandboxed `srcdoc` iframes are missing, and also returns false unless the environment is on an explicit verified list (see 3). Unsupported or unverified means "use the clip", never "try anyway".
- Everything must clean up after itself: `destroy()` removes the iframe, terminates the Worker, closes bitmaps, clears timers and listeners.

### 2. The player: `frontend/lib/live/plate-player.ts`
Implement `ScenePlayer` (`frontend/lib/live/types.ts`) for one plate scene (and a small `createFilmPlayer` that sequences several scene players on one timeline using `PlaybackClock`), using the existing `FrameCache` and `FrameScheduler`:
- The cache key is `bundleDigest | frame | previewSize` (digest comes from the bundle route). The window is derived from the byte budget exactly as in plan section 6 (`windowFrames = floor(budgetBytes / bytesPerFrame)`, split 20 % behind, up to 15 frames head of the next scene, the rest ahead). Budget `LIVE_CACHE_MB`: 160 default, 80 when `navigator.deviceMemory <= 4`, 60 on iOS. If the existing cache or scheduler assumes whole-scene pinning or a main-thread draw slice, adapt them (keep their public behaviour tested; update tests only to follow a documented contract change, never to weaken coverage) and list every change in the report.
- **Gate (section 6 and section 20):** playback starts when `bufferedAhead >= lead`, with `lead = clipSeconds * max(0, 1 - produceFps / consumeFps) + 0.5 s` measured from the running average of draw cost, using the actual ahead capacity. If `lead` exceeds the ahead capacity, or the host reports `unhealthy`, or `supportsWorkerHost()` is false, the player reports `mode: "clip"` through an event and does not draw. Expose `decision(): { mode: "live" | "clip", reason: string }`.
- **Audio is the master clock:** `showFrame(frame)` never blocks; a frame not yet drawn keeps the last good frame, and `buffering` events fire. Seek re-prioritises the scheduler.
- **Preview size:** 854x480 for 16:9 (480x854 for 9:16, 640x640 for 1:1); the Worker is mounted at the matching scale.
- Frames are drawn to the target element's `<canvas>` with `drawImage(bitmap)` on the page; the player owns that canvas.

### 3. API client and environment gate: `frontend/lib/live/api.ts`, `frontend/lib/live/support.ts`
- `fetchBundle(projectId, variantId)` returns `{ html, bundleDigest, manifest, params, expiresAt }`: calls the bundle route, then fetches the presigned `url`; verifies the HTML's sha256 (full) against the manifest's `bundleSha` prefix when present and refuses to run a bundle that does not match; refreshes an expired link once.
- `reportCheck(projectId, variantId, { gen, bundleDigest, results, device })` posts to the check route (host is always `"worker"`); treats 204 as "dropped, fine", and never throws on a network error (returns a status).
- `requestClip(projectId, variantId)` posts to `clip-request` and surfaces 429 `clip_cap` as a value, not an exception.
- `runCheck(host, meta)` runs the browser check from plan section 7 in the Worker host: no errors from init, `meta` matches the manifest (size, fps, frames), frames 0, middle and last drawn twice give identical bytes (determinism), and reports `{ ok: true }`, `{ ok: false, kind: "code", error }` for scene failures, or `{ ok: false, kind: "env" }` when the device could not draw (worker unsupported, out of memory, terminated by the watchdog on the first frame).
- `support.ts` holds the verified-environment list as data: Chrome and Chromium-based browsers at version 120 or newer on desktop only (macOS, Windows, Linux) are `verified`; Safari, Firefox, iOS and Android are `unverified` (they get the clip until someone adds measured results to the list). Export `environmentStatus(): "verified" | "unverified" | "unsupported"` from the user agent and feature detection, with unit tests for the table.
